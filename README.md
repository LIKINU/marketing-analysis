# Marketing Analysis · 企业营销与商业模式分析器

> 给一个企业名，产出一份**对标 MBB / 4A 的分析报告**（Markdown + Word）。
> **只做拆解与解读，不出执行方案。** 把「该不该信这个结论」变成可机械检验的问题。

一套纯 Markdown + Python 写的分析 skill：**骨架由脚本生成、判据由脚本执行**——不依赖模型自觉。
任何能读文件、或能接受粘贴的 AI 都能用：Claude Code / WorkBuddy / Cursor / ChatGPT / 豆包 / 本地 Agent。

---

## 这是什么 / 不是什么

| ✅ 是 | ❌ 不是 |
|---|---|
| 分析师视角的**拆解与解读**：商业模式怎么赚钱、营销手法怎么打、哪里最脆 | 执行方案（排期、预算分配、行动清单） |
| 结论**可被证伪**：议题树 + 假设台账 + 被证伪记录留档 | 数据堆砌（每条数字都要求来源与口径） |
| **机械判据**兜底：27 项审计 + 62 项回归断言，不过关不出稿 | 自评「我觉得写得不错」 |
| 明确**责任边界**：四件事必须人签字 | AI 代签结论与合规 |

## 30 秒上手

### A. 有 skill 机制的平台（Claude Code / WorkBuddy 等）

```bash
git clone git@github.com:LIKINU/marketing-analysis.git
# 放进平台的 skills 目录（用户级或项目级），或直接在该目录里工作
```

触发语：「分析 XX 公司」「拆解 XX 的营销」「商业模式分析」「对标顶级咨询」。

### B. 有知识库的平台（ChatGPT Projects / 豆包 / 飞书知识库）

把 `SKILL.md` 放进去，自订指令写：「处理企业分析时，先读 SKILL.md 并依其流程执行」。

### C. 纯对话环境（豆包 / ChatGPT / 其他）

> ⚠️ **这类平台跑不了 `composer.py`** —— 骨架必须**直接复制**，不要让模型自己编结构。

1. **先贴骨架**：`skeletons/骨架-<体裁>-<深度>.md`（9 份可选，不确定就用 `-标准`）
2. **再贴规则**：`SKILL.md` 的门禁 + 七步工作流 + 纪律三段
3. **补一句**：「按这份骨架逐个小点填写，『必含 / 句式 / 查 / 反例』四件套都要满足」
4. 要素材再贴 `references/` 下的对应档——**为「按需加载」设计**，不用一次贴完
5. **交付前自查**：骨架里每个小点的「必含」逐项对照产出，缺项补。**降级不等于跳步。**

## 工作流（七步，顺序不可跳）

```
0 门禁（8 项一次问全）→ 出《任务规则表》等确认
1 议题树与假设   每条分支可证伪 + 写清作废条件
2 事实检索       只查能证伪假设的信息，三级可信度标注
3 故事线         ghost deck：先写标题（必须是结论句），再填内容
4 章节填充       骨架由脚本生成，逐个小点填
5 压力测试       Red Team ≥3 条最强反方 + Pre-mortem
6 交付门禁       一条命令跑完全部判据，不过关不出稿
7 交付后复盘     新学到的东西回写知识库（不跳）
```

## 固定骨架：3 体裁 × 3 深度档

骨架**不手写**，由 `scripts/composer.py` 机械生成；每个小点自带**填空规格四件套**（必含分项 / 句式模板 / 该查哪一节 / 反例）。

```bash
python scripts/composer.py --out 骨架.md --tier 全量分析 --depth 标准
python scripts/composer.py --check 报告.md      # 缺章 / 小点过薄 → 不合格
python scripts/composer.py --spec-audit 全量分析 # 规格与基线核对
```

| 体裁 | 章 / 小点 | 什么时候用 |
|---|---|---|
| **全量分析** | 17 章 / 46 小点 | 常规深度交付 |
| **对标研究** | 12 章 / 34 小点 | 横向比同行、找坐标 |
| **尽调式拆解** | 14 章 / 36 小点 | 要下判断、要承担后果的场合 |

| 深度档 | 效果 |
|---|---|
| 快档 | 每章留 2 小点、字数目标 ×0.6（先看结论、时间紧） |
| **标准** | 默认 |
| 深度 | 字数目标 ×1.25（尽调级） |

**章序固定**：**外部与内部诊断**（三、PEST／波特五力／SWOT／BCG）→ 先拆**商业模式**（四、收入结构／单位经济／价值链位置／脆弱点／毛利·流水·ROI）→ 再拆**营销手法**（五、STP 客群与定位／4P 产品·价格·渠道·内容·投放·活动／私域复购／AARRR 增长链路／打法识别／流失点）。
商业模式章有**小点数下限基线**锁定——不会为了加厚别章而被削薄。

## 判据与护栏（机械判，不靠自觉）

```bash
python scripts/gate.py 报告.md --words 8000 --dep 被引文件.md --dep-trust auditor
```

一条命令跑完全部 7 项，输出一屏汇总，任一项不过即不可交付：

| 判据 | 内容 |
|---|---|
| 议题树 | MECE + 假设可证伪 |
| 标题 | 必须是结论句（禁主题词标题） |
| 来源 | 含数字句的来源覆盖率 ≥80% |
| 图表 | 一图一结论 + SOURCE + 口径 + y 轴原点 |
| 引用可解析 | **幻影引用＝硬错误**；未验证＝阻断（不扣分但不出门） |
| 骨架完整性 | 缺章 / 小点内容过薄 → 不合格 |
| 交付审计 | **27 项**（5 维度族；**8 类硬错误**） |

另有 **58 项回归护栏**（`scripts/smoke_test.py`）：含作弊稿、幻影引用、误杀回归——**审计器自带反作弊**，零分析但格式齐的稿子会被打到不合格。

**Word 交付（客户可直接用）**：以 `assets/交付模板.docx` 为底稿，**自动加封面（标题/客户/交付方/日期）与页脚页码，并剥掉全部 `<!-- -->` 内部注记**。

```bash
python scripts/md2docx.py 报告.md 报告.docx \
    --title "客户名 营销与商业模式分析报告" --client "客户：XX" \
    --author "交付方：XX" --date 2026-09-23 --footer "XX · 拆解报告"
python scripts/deliver_check.py 报告.docx --docx --title "客户名 …"   # 确认可以直发客户
```

正文排版规范见 `references/18-交付格式规范.md`（只指定样式名，不手搓字体字号）。

## 常见问题

**卡死了怎么办？** 同一项校验连续 2 次不过 → 停下摊给用户，给 2–3 个选项；脚本报错 → 降级 Markdown 继续产出；用户说跳过 → 允许，但必须声明未校验并列出未通过项。**强制不得变成卡死。**

**没有代码执行能力能用吗？** 能。退回手工对照清单 + 原样输出自检项 + 附样式对照说明。判据的严格程度不降。

**引用外部文件为什么非要传文件本身？** 因为「引用可解析」这条判据要拿报告里的引用与**真实文件**逐条对账——只凭名字无法判断真伪。审计者传错参数 ≠ 报告有缺陷，两者分开显示。

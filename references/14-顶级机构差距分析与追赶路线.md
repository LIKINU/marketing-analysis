# 14 · 顶级机构差距分析与追赶路线

> **这是什么**：本 skill 与 MBB（麦肯锡/BCG/贝恩）＋ 4A 交付标准的多维度差距分析，含实测证据、差距分类、结构性改造清单与剩余边界。
> **什么时候读**：**只在被点名时读**（见 `../SKILL.md` 知识库路由表）；不要通读。
> **读完你能**：知道哪些差距已经闭合、哪些是能力边界、下一步该补哪一块。
> **规模**：约 0.6 万字

## 一、这份差距是怎么量出来的（口径先行）

差距不能靠感觉说，所以先把三件事摆到台面上：

**① 判据来源（外部优先，不用自家文档给自己打分）**

| 来源类型 | 具体依据 |
|---|---|
| MBB 方法论与交付惯例 | McKinsey Staff Paper 69《The McKinsey Approach to Problem Solving》（假设树 / Day-1 answer / MECE）；Barbara Minto 金字塔原理与 SCQ；Bain Results Delivery（owner/timeline/resource、变革阻力）；BCG 假设驱动 + issue tree（「没有 issue tree 就写正文 = 不合格」）；Slideworks/Umbrex 等对 MBB 幻灯片与 QC 惯例的整理（action title、one exhibit = one message、SOURCE 行、partner review、pre-wiring） |
| 4A 与实效评审官方规则 | Effie 四段权重（挑战与目标 23.3% / 洞察与策略 23.3% / 创意落地 23.3% / **结果 30%**）；Cannes Lions 创意实效类（创意 25% / 策略 25% / **影响与结果 50%**）；IPA 实效奖四要件（效应与因由相关、相关非巧合、机制清晰、**排除其他解释**）；APG 策划评审（策略主张 × 创意表达 × 两者联结）；WARC 创意实效六级阶梯 |
| 2026 新增硬规 | ESOMAR/ICC 2025 第五版（合成数据须定义并标注、须说明人工监督程度、阈值以下不得外推）；EU AI Act 第 50 条（2026-08-02 起，逼真合成人像/合成代言人须显著标识 + 机器可读标记）；GDPR/PIPL（同意版本留痕、拒绝与接受同等显著） |
| 知识库既有标尺 | `13-顶级机构对标标准.md`（16 条可判定标准 + 0–5 评分口径）、`09-完整策划标准与评分表.md` §3.2 咨询公司级四维（问题定义/逻辑/可落地/有增量，各 25%） |

**② 打分口径（第三方可复现）**：0 = 完全找不到；1 = 只在标题/口头提到；2 = 有正文但换个人读结论不同（靠自觉）；3 = 有脚本能机械判定「有没有」；4 = 有脚本判定「够不够格」，换新样本能复现同样判定；5 = 机械机制之外还有「人」把最后一关（顶级所是合伙人签字）。

拿知识库里**自家最得意的成品**（`references/范例/便利店开学季战役-交付稿.md`，8958 字）跑新写的 `scripts/mbb_audit.py`：

| Red Team / pre-mortem | 0 条 | ≥3 条反方论点 | 高 |

## 三、差距归类：不是所有差距都该用同一种方式补

| 差距类型 | 数量 | 特征 | 正确的补法 | 错误的补法 |
|---|---|---|---|---|
| **结构性** | 5 | 流程顺序错、骨架缺章（如「先写正文再补树」） | 改 SKILL.md 的工作流顺序与骨架 | 写更多知识文档（知识再多也改不了顺序） |
| **纪律性** | 11 | 判据清楚，只是没人查 | 写脚本机械判定 + 硬错误拦截 | 靠「提醒自己要检查」 |
| **知识性** | 3 | 知识库有素材但没接上流程（洞察、利益相关者） | 接进骨架必填章 + 路由到 references | 再拷一批案例进来 |
| **能力边界** | 1 | 一手信息不可得 | **诚实标注 + 用「可验证检索流程」替代** | 假装有专家访谈、编数据 |

> **一句话根因**：改造前最大的问题不是「知识不够」，而是**顺序错 + 没护栏**——29 分的成品背后，知识库里躺着 116 条打法与 111 个模型。

## 五、代码级护栏清单（新增 6 支脚本）

| 脚本 | 机械判定什么 | 判定不过的后果 |
|---|---|---|
| `scripts/issue_tree.py` | 顶层分支 3±2、反证条件 ≥3、遗漏检查句、假设台账、被证伪记录 | 议题树不通过 → 不许开写正文 |
| `scripts/storyline.py` | 标题结论句占比 ≥80%、主题词标题 = 0、通读测试 | 不通过 → 标题重写，禁止定稿 |
| `scripts/source_ledger.py` | 来源覆盖率、泛引用、**【未核实】泄漏**、口径说明 | 不通过 → 禁定稿，并输出台账待补清单 |
| `scripts/chart_check.py` | 每图标题为结论句、100% 有 SOURCE、口径说明、一图一信息、y 轴原点说明 | 不通过 → 图表不合格，禁止定稿 |
| `scripts/mbb_audit.py` | 25 项 × 5 维度族（A25/B25/C20/D10/E20）+ 5 类硬错误 | 总分 <85 或有硬错误 → 打回重写 |
| `scripts/smoke_test.py` | 用正/负夹具 + **作弊夹具**验证上面五支**真的能拦**（20 项断言，含误杀回归） | 负向夹具未拦下 = 护栏失效，必须修脚本，不许放宽判据 |

**防伪设计（对应差距 #19）**：分数由脚本给出，生成者只能用 `--json scorecard.json` 贴原文，不能自行填写分数；`smoke_test` 保证「护栏本身不会静默失效」——这是顶级所靠「人盯人」做不到、而机械机制能超过中型公司的地方。

## 六、仍然追不上的（诚实边界，不许假装）

| 追不上的东西 | 为什么 | 本 skill 的替代做法 |
|---|---|---|
| **一手信息** | 没有专家网络、没有专有数据库、没有渠道实测；案例与数据都是二手 | 把「该查什么、去哪查、查不到怎么写」写成流程；关键结论标注证据等级 |
| **判断力与责任** | 顶级所在信息不全时押方向并为此负责；本 skill 只能保证「不跑偏、要素齐、逻辑自洽」 | 把假设显式化 + 标明证伪条件，让人类决策者承担判断 |
| **效果数据（因果证据）** | 增量测试/地理对照需要投放预算与实验设计 | 明确区分相关性证据与因果证据；不给没有依据的效果承诺 |
| **合伙人签字那一关** | 5 分口径的最后一位是人 | 用「脚本判定 + 用户逐条验收」双重把关，但不冒充专业判断 |
| **行业人脉与落地资源** | 顶级所卖的一半是执行 | 明确不承诺落地结果 |
